Guidance for any coding agent working in this repository. **This file is the
shared source of truth** — everything an agent needs to work here is below,
or in the docs it links, regardless of which harness it runs in.

Harness-specific files complement it and must not restate it:

| File | Scope |
| --- | --- |

| `CLAUDE.md` | Claude Code specifics only — it imports this file |

Keep new project knowledge in this file. If a fact holds for every agent, it
belongs here even when you discovered it in one harness. Design detail of one
component goes in its doc (`docs/pipeline-architecture.md`,
`docs/csms-architecture.md`, `docs/testing.md`), with its summary kept here.

## What this repository is

A curated "awesome list" of EV charging protocol tools (OCPP, OCPI, ISO 15118, OICP, eMI³, OIOI, Eichrecht). Four deliverables live here:

1. **`README.md`** — the published awesome list. Its prose (intro, `## Specifications`, `## Regulation & Standards Bodies`, `## Smart Charging & Grid Integration`, `## Testing & Conformance`, `## Open Data`, `## Contributing`) is hand-authored; `## Contents` is regenerated by `render`. The **project listing** inside `## Tools and Resources` — everything between the `<!-- BEGIN GENERATED PROJECTS -->` / `<!-- END GENERATED PROJECTS -->` markers — is **generated** by `python pipeline.py render --readme README.md` and injected in place. Do **not** hand-edit between those markers; edits are overwritten on the next render. To change what appears there, adjust the pipeline inputs (see Conventions) and re-render.
2. **`pipeline.py`** — a discovery pipeline that scrapes GitHub for candidate repositories, scores them with quality signals, AI-classifies them, and renders the curated project listing that populates the README's `## Tools and Resources` block.
3. **`csms.md` + `csms.py`** — a separate product-level catalogue of Charging Station Management Systems (see "csms.py" below). Independent of `pipeline.py`, which it only imports.
4. **`site/`** — a static Astro site (GitHub Pages) that reads the `data/*.json` export and `README.md` at build time. A reading view only: the README and the CSVs stay authoritative. A separate npm package (`site/package-lock.json`); Node is pinned in `mise.toml`. See [docs/site.md](docs/site.md).

The repo also vendors protocol specifications as static assets under `ocpp/`, `ocpi/`, `oicp/`, `emi3/`, `eichrecht/`, `nemo/`, `oscp/` (PDFs, WSDLs, JSON schemas, pinned by `tests/vendored_assets.sha256`) — these are reference material linked from `README.md`.

## Commands

The project is managed with **mise** (`mise.toml`): it pins Python 3.11.16 and
Node 22.23.5 (for `site/`), and auto-creates/activates a `.venv` — no manual
`source .venv/bin/activate`. Run
`mise trust` once after cloning.

```bash
mise install          # install the pinned Python
mise run install      # (alias: mise run i) runtime deps into .venv
mise run install-dev  # runtime + pytest; `install` alone keeps the CI data job lean
#   A fresh .venv has no pytest — run this before `mise run test`, or the suite
#   fails with "No module named pytest" and it looks like a broken environment.
mise run test         # (alias: mise run t) pytest

mise run ingest       # Stage 1 -> repos.csv   (wires --token via `gh auth token`)
mise run enrich       # Stage 2 -> repos.enriched.csv

# Or call the script directly (mise auto-activates .venv for commands run in-dir):
python pipeline.py ingest --token <GITHUB_PAT> --out repos.csv
python pipeline.py enrich --in repos.csv --out repos.enriched.csv --token <GITHUB_PAT>
#   enrich flags: --limit N / --skip-forks / --skip-dormant / --refresh
#   / --restamp [--reask-category 'Main > Sub' ...] (after a prompt edit)

python pipeline.py render --readme README.md   # Stage 3 -> injects the curated
#   Selection between the markers in README.md and writes the secondary
#   legacy-projects.md (dormant + to-refine). Omit --readme to only write the latter.
#   Add --export-dir data to also write data/projects.json + its manifest entry.

git show HEAD:classifications.csv | python pipeline.py check-classifications --base -
#   CI guard, see "Classification guard" in docs/pipeline-architecture.md. Optional:
#   --report report.md [--base-projects base.json [--projects data/projects.json]]

mise run discover     # external lists -> discovery-report.md (git-ignored)
python discovery.py --sources discovery-sources.toml --report <path> [--token T]
#   Read-only review report, see "discovery.py" below. Run from the repo root.

mise run site-install # npm ci in site/
mise run site-check   # astro check + vitest + build against site/fixtures/data + link check
mise run site-build   # build from AEC_DATA_DIR (default ../data, relative to site/)
mise run site-fixture # regenerate site/fixtures/data/ after an exporter change
```

`--token` is optional; without it GitHub's unauthenticated rate limits apply.
`gh auth token` supplies one when the gh CLI is authenticated.

`mise run test` (alias `t`) runs the pytest suite in `tests/`. One line per
file below; what each covers in detail is in
[docs/testing.md](docs/testing.md).

- `tests/test_csms.py` — `csms.py` and the committed CSVs, no network.
- `tests/test_pipeline.py` — `pipeline.py`'s classification layer, backend and
  README fetch stubbed, no network and no LLM CLI.
- `tests/test_discovery.py` — `discovery.py` and the committed
  `discovery-sources.toml`, HTTP stubbed, no network.
- `tests/test_vendored_assets.py` — pins every vendored file with
  `tests/vendored_assets.sha256`; after a deliberate change, update the
  inventory and run `python tests/vendored_manifest.py --write`, never
  regenerate to silence an unexplained change.
- `tests/test_oscp_schemas.py` — the defects and local patches of
  `oscp/OSCP-2.0/`.
- `tests/test_public_export.py`, `tests/test_csms_export.py`,
  `tests/test_public_data.py` — the public JSON export and `data/schema/`.
- `tests/test_markdown_links.py` — every relative or own-repo link resolves to a
  tracked path, case-sensitively; `VENDORED_LINK_EXCEPTIONS` takes exact
  `(file, target)` pairs, never a skipped file.
- `tests/test_site_fixture.py` — `site/fixtures/data/` is a fresh render of
  `site/fixtures/repos.enriched.csv`; fix with `mise run site-fixture`.

Markdown is linted by `npx markdownlint-cli2` (config in
`.markdownlint-cli2.jsonc`): every tracked `*.md`, dot-directories and the
first-party files under the vendored directories included. Only the three
verbatim OCA files `ocpp/OCPP-2.0/ReadMe.md`, `ocpp/OCPP-2.0.1/ReadMe.md` and
`ocpp/OCPP-2.1/ReadMe.md` are exempt, by exact path: they are upstream bytes,
never reformatted. The exemption covers style only: they stay in the
provenance and licence inventory of `docs/third-party-assets.md`, and their
bytes are pinned by `tests/vendored_assets.sha256`. The
live classifier prompt `.claude/agents/repo-classifier.md` keeps its bytes too,
with three rules relaxed for it alone. `README.md` is additionally checked by
`npx awesome-lint`.

In a git worktree (agent stacks put them under `.context/`):

- `npx` goes through mise, which refuses an untrusted `mise.toml`: prefix it
  with `MISE_TRUSTED_CONFIG_PATHS=$PWD` instead of trusting the worktree.
- awesome-lint rejects a worktree (its `.git` is a file) and a branch with no
  upstream (`remark-lint:awesome-github`): run it in a throwaway `git clone`
  of the GitHub URL, after copying the worktree's `README.md` over the
  clone's, so the lint reads your changes, not `main`'s.
- Reuse the main checkout's interpreter: `<main>/.venv/bin/python -m pytest`,
  run from the worktree root, imports the worktree's modules.

## pipeline.py architecture

A two-stage pipeline connected by a **CSV boundary**: `ingest` writes
`repos.csv`, `enrich` classifies it into `repos.enriched.csv`, reusing the
committed `classifications.csv` while `classifier_signature` matches. After an
edit to `CATEGORY_TREE` or `CLASSIFIER_INSTRUCTIONS`, run `enrich --restamp`,
not `--refresh`. `check-classifications` is the monthly workflow's gate.
Details: [docs/pipeline-architecture.md](docs/pipeline-architecture.md#ingest).

## csms.py — the CSMS catalogue

A **deliberately separate script** from `pipeline.py`: that module is GitHub discovery, this one mirrors a non-GitHub registry. It `import pipeline` purely to reuse `auth_headers`, `get_repo_data`, `_inject_between_markers`, `CACHE_DIR` and `CACHE_TTL`. **Do not fold it back into `pipeline.py`.**

```bash
python csms.py fetch    # -> csms-certificates.csv (OCA registry mirror)
python csms.py render   # -> injects the tables into csms.md + csms-features.md
python csms.py render --export-dir data   # ... and writes data/csms.json + its manifest entry
mise run csms           # fetch + render --export-dir data, with the gh token wired in
```

**The curated CSVs are canonical; the Markdown is only a view.** Nothing may
appear in `csms.md` / `csms-features.md` / `data/csms.json` that cannot be reconstructed from
`csms-certificates.csv` + `csms.csv` + `csms-features.csv` and the rules in
`csms.py`.

`csms-certificates.csv` is never hand-edited; no script ever writes `csms.csv`,
and every curated value needs a source URL.
Certification and source availability are derived, never typed; certified and
vendor-documented features are never merged; `Source available` is never `N`.
Only merge two registry products when the certificates clearly describe one
platform. Details: [docs/csms-architecture.md](docs/csms-architecture.md#fetch).

## discovery.py — external-list discovery

A **separate script**, like `csms.py`: it imports `pipeline` for the HTTP
cache, the README fetch and the README scan. It reads the lists configured in
`discovery-sources.toml` (forks and other awesome lists; a new source needs
no code change), compares what they link with the catalogue, and writes a
deterministic review report with one status per candidate: `new`, `changed`,
`unavailable`, `excluded` or `existing`. **It never writes curated data**:
acting on the report goes through the usual workflows (`add-project`, ...).
`.github/workflows/discovery.yml` runs it weekly, publishes the report as an
artifact and keeps one rolling issue labelled `discovery-report`, edited only
when the report changed, with external mentions and issue references
neutralised. Details: [docs/discovery.md](docs/discovery.md).

## Agent configuration

Each harness keeps its own copy of the same two things, and they drift silently
if only one is edited:

| Path | Used by | Holds |
| --- | --- | --- |
| `.claude/agents/repo-classifier.md` | Claude Code, and `enrich --classifier claude` | The classifier role + output contract |
| `.codex/agents/repo-classifier.toml` | Codex | The same contract, in TOML |
| `CLASSIFIER_INSTRUCTIONS` in `pipeline.py` | `codex` and `copilot` backends | The same contract, in-prompt |
| `.claude/skills/` | Claude Code (`/add-project`, `/refresh-metadata`) | The two maintenance workflows |
| `.agents/skills/` | Any other harness | Harness-neutral copies of the same two |

Change the classifier's role or output shape in one place and you must change
it in the other three — `parse_classification` parses one format for all of
them.

## Conventions

- `repos.csv` / `repos.enriched.csv` are generated artifacts (git-ignored). `classifications.csv` is the durable, committed LLM cache. `cache_github/` is regenerable API-response cache — treat it as disposable, not source.
- The `## Tools and Resources` project listing is **generated** — do not edit it by hand in `README.md`. To add/remove a repo there: it must be discoverable by `ingest` (via a `TOPICS` match, a curated stars-list entry in `STARRED_LISTS`, an `ADDITIONAL_REPOS` entry, a `CODEBERG_REPOS` entry for a Codeberg-only repo, or a GitHub link elsewhere in `README.md`), then `enrich` and `render --readme README.md`. Use `EXCLUDED_REPOS` to drop one. Promotion tier (which decides `Selection` vs `To refine`) is driven by the star lists / contributor status, not by manual ordering.
- `data/` (`projects.json`, `csms.json`, `manifest.json`) is generated by the two renders with `--export-dir data`, committed, and **never hand-edited**; `data/schema/` holds the hand-written JSON Schemas versioned with it. A change to canonical data regenerates `data/` in the same PR.
- **No AI attribution in commit messages.** No `Co-Authored-By:` trailer naming an assistant, and no mention of one in the body. Standing rule from the repo owner.
- **An empty cell means unknown, never "no".** This holds across both deliverables and is the reason curated values require a citable source: absence records what we could not verify, not a property of the thing. Do not "complete" a table by inferring a negative.

## Stage 3 — `render` → README (Selection) + legacy-projects.md

`render` partitions rows into `Selection`, `Dormant` and `To refine`
(`_curation`) by promotion score and activity. The **README publishes only
`Selection`**, awesome-lint-clean; the other two go to `legacy-projects.md`.
With `--readme README.md` it replaces the project and `## Contents` regions
between their markers, and aborts if a marker pair is missing or out of order.
Details: [docs/pipeline-architecture.md](docs/pipeline-architecture.md#stage-3--render--readme-selection--legacy-projectsmd).

## Public JSON export — `data/`

`render --export-dir data` (both scripts) writes a public JSON view of the same
data; `docs/public-data.md` is the consumer contract. `PUBLIC_SCHEMA_VERSION`
must match the `const` in `data/schema/*.schema.json`. `data/projects.json` is
not committed yet (issue #98). In `refresh-metadata.yml` the CSMS steps run
before the project render. Details:
[docs/pipeline-architecture.md](docs/pipeline-architecture.md#public-json-export--data).
