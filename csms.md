# Charging Station Management Systems (CSMS)

A CSMS is the backend a charging station talks to over OCPP. This file lists the
ones we can document from verifiable sources, in one table, so the two questions
that usually matter — *is it certified?* and *can I read the source?* — are
columns rather than separate lists. They cross more often than expected:
CitrineOS is both, while SteVe is source-available but not certified — its
maintainers ship a separately certified commercial build under another name.

This is a companion to the [main list](README.md), which covers tools and
libraries rather than products.

- **[How this catalogue is built](docs/csms-methodology.md)** — sources,
  inclusion rules, feature derivation, deduplication, and what each column is
  allowed to mean. Read it before drawing conclusions from the table.
- **[Feature annex](csms-features.md)** — per product, what an OCA certificate
  proves and what the vendor documents, each with its source.

## Four caveats worth reading first

**An empty cell means *unknown*, never *no*.** Curated values need a citable
source; a contributor who cannot cite a fact leaves the cell empty. Absence is a
statement about our research, not about the product.

**OCA certification applies to a product and a software version, not to a
brand.** Each certificate links to the PDF naming the exact version tested. An
empty `OCA certificates` cell means no certificate was found in the registry —
certification is voluntary and paid for, so it is not a failed assessment.

**A feature nobody documented is not a missing feature.** Certificates
under-report by design, and vendor documentation is incomplete by nature.

**`Source available` is not an open-source licence.** It means the source code is
publicly accessible. Licence terms are tracked separately in the `license` column
of `csms.csv` — check them before assuming any right to reuse, modify or
redistribute.

## The directory

`Product` links to the vendor's site (or its repository), `Company` to its OCA
participant page. `API` is `Y` when a reliable source documents an API, linked
when that documentation is public and unlinked when it sits behind a login.

## Contributing to this list

The table between the markers above is generated by `python csms.py render` — do
not edit it by hand. Three data files feed it, and
[CONTRIBUTING.md](CONTRIBUTING.md#adding-or-correcting-a-csms-entry) has the full
procedure.

- **OCA data** lives in `csms-certificates.csv`, a mirror refreshed by
  `python csms.py fetch`. Never edit it; corrections belong upstream with the
  Open Charge Alliance.
- **Products** live in `csms.csv`, the canonical curated dataset, which no script
  ever writes. Add a row there to introduce a non-certified product, or to attach
  facts the registry does not carry. It keeps more columns than the table shows
  (HQ, founding year, pricing, licence, ISO 15118, Eichrecht, release history).
- **Vendor-documented features** live in `csms-features.csv`, one row per
  product, feature and source.

Every curated value needs a URL — in the product row's `sources` column, or in
the feature row's `source_url`. If you cannot cite it, leave it out.
