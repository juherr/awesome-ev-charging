# CSMS feature annex

Companion to the [CSMS directory](csms.md). One row per product, with the two
kinds of evidence kept apart:

- **Certified (OCA)** — derived from the certificate type the Open Charge
  Alliance published for that product. Proven by a certificate, whose PDF is
  linked from the [directory](csms.md).
- **Vendor-documented** — capabilities the vendor documents publicly, curated in
  `csms-features.csv`. Each one links to the source that documents it.

A feature may legitimately appear on both sides. The reverse never happens:
vendor documentation does not turn into certification.

**Neither column is an inventory.** Certification is opt-in and costs money, so
it under-reports by design; vendor documentation is incomplete by nature. An
empty cell means *nothing we can cite says so*, never *the product cannot do it*.

Feature names come from a controlled vocabulary shared by both columns, so the
two stay comparable — see
[how this catalogue is built](docs/csms-methodology.md#features-two-kinds-of-evidence)
for the derivation rules, the OCPP 1.6 `Full` inference, and which sources are
acceptable.
